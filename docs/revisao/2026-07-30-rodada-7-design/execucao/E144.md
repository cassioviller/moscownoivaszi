# E144 — a pergunta "este orçamento já virou contrato?" custa uma linha, não o acervo

**Passada de sobras, sessão 1** · branch `rodada-7-sobras` · base `d7c2b7b` (E143)
Fecha: S-D16 🟡
Suíte: API 876 → 877 · frontend 417 · E2E 147 · typecheck verde

## O achado

`orcamentos/[id].tsx:235` baixava a lista COMPLETA de contratos da loja —
**615.041 bytes medidos no banco de dev (518 contratos)** — para um único
`find(c => c.orcamentoId === id)` que só decide se o botão diz "Gerar
contrato" ou "Ver contrato", e só quando o orçamento está APROVADO. O E124
deu página à rota, mas esta chamada não podia paginar: o find precisava do
acervo inteiro para ter certeza do "não tem".

## O conserto

A mesma classe do `?leadId=` do E62: **`?orcamentoId=` no
`GET /lojas/{lojaId}/contratos`** (openapi → codegen → uma condição `eq` na
rota), e a tela passa a pedir só o contrato daquele orçamento — a resposta é
1 item ou vazia, nunca o acervo. A invalidação existente
(`getListContratosQueryKey(lojaId)`, chave-prefixo) continua alcançando a
query parametrizada, então gerar o contrato segue atualizando o botão.

## Verificação

- **Vermelho antes, literal:** o teste novo do e124-acervo, rodado com a rota
  ainda ignorando o parâmetro, caiu em `expected 3 to be 1` — a rota devolvia
  os 3 contratos da fixture onde o filtro devia devolver 1.
- Depois da condição na rota: e124-acervo **8/8** (o caso novo prova o recorte
  com contrato E o vazio com `total: 0`, que é o que alterna o botão).
- Suítes completas: API 877, frontend 417, E2E 147 (o spec 52,
  orcamento-vira-contrato, atravessa esta tela), typecheck — verdes.

## O que o executor errou

A primeira versão do teste novo criava orçamentos e um contrato ATIVO nas
noivas compartilhadas da fixture, ANTES dos testes que pregam contagens
(`?status=` afirma `total: 2`; os de orçamentos afirmam 1 por noiva) — teria
quebrado três vizinhos. Caiu na leitura, antes de rodar: o teste foi refeito
com noiva própria ("Clara Filtro E144") e movido para o FIM do describe, com
o comentário dizendo por quê.

## Visto de passagem

- O `find` da tela ficou como cinto de segurança sobre a lista já recortada
  (custa nada e protege contra um cache de outra chave). Nenhuma sobra nova.
