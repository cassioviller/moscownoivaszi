# E141 — ⌘K: a busca de noivas a um atalho de qualquer tela

**Rodada 7 (design), sessão 7** · branch `rodada-7-design` · base `2e2a8a3` (E140)
Fecha: **D6 🟡** (a noiva no telefone, a vendedora em qualquer tela: sidebar →
Noivas → campo → digitar → Detalhes, 3 cliques + digitação toda vez — e sair
de um formulário descartava o que estava digitado).
Suíte: API 873 · frontend 417 · E2E 147 · typecheck verde

## A primeira ação: o número que não podia piorar

`PORT=5173 BASE_PATH=/ pnpm build`, ANTES: entrada `index` **333,87 kB**
(gzip 105,39) + `modulepreload` react 185,71 + api-client 101,10.

## O conserto

- **`components/busca-global.tsx`** (lazy): um `Dialog` + `Command
  shouldFilter={false}` com a MESMA busca server-side das listas
  (`listLeads?q=`, `ordem: "recentes"`, debounce 300ms, 8 resultados) —
  nome, noivo e dígitos do WhatsApp, como o D6 pedia. Enter/clique navega
  para a ficha com escopo de loja e fecha.
- **`app-layout`**: o listener de ⌘K/Ctrl+K (com `preventDefault` — ganha do
  atalho do navegador — e MUDO com o foco em input/textarea/contenteditable,
  cuidado b), o gate `podeNoModulo("leads","ver")` espelhando o servidor
  (cuidado c), e o diálogo entra por `lazy` + `Suspense`, montado só depois
  do primeiro uso.
- **Gatilhos visíveis**: o ícone de busca ao lado do sino — na sidebar
  (desktop) e no header mobile — com `aria-label` "Buscar noiva (Ctrl+K)".
- As entradas de navegação "de carona" do backlog foram CORTADAS (o próprio
  backlog: "cortável sem culpa") — o épico é a busca de noivas.

## Verificação

- **Bundle, remedido** (cuidado a): entrada **335,08 kB** (gzip **105,77**,
  **+0,38 kB**) — o custo no caminho crítico é o listener e dois botões; o
  diálogo inteiro vive num chunk lazy de **1,59 kB** (`busca-global-*.js`)
  que só desce no primeiro ⌘K. Preloads inalterados.
- **No app vivo, os três comportamentos**: Ctrl+K abre de /financeiro; a
  busca por "E2E Noiva Playwright" traz o resultado (a query é a do servidor
  — o `shouldFilter={false}` existe porque o filtro client do cmdk
  descartaria o resultado de uma busca por dígitos) e o clique navega à
  ficha; com o foco num input de busca de outra tela, Ctrl+K NÃO abre.
- **Suítes**: frontend **417/417** · API **873/873** · **E2E completo
  147/147** · typecheck verde.

## O que o executor errou

O primeiro desenho usou o `CommandDialog` pronto — que não repassa
`shouldFilter` — e o smoke pegou a lista vazia: o cmdk filtrava os itens pelo
`value` (uuid) contra o texto digitado. A regra que fica: **cmdk sobre busca
de SERVIDOR é sempre `shouldFilter={false}`** — o combobox de noivas já sabia
disso (`shouldFilter={false}` desde o E63), e a lição estava a um grep.
