# E129 — O filtro sobrevive à navegação: as 6 telas de `useState` passam para a URL

**Rodada 7 (design), sessão 7** · branch `rodada-7-design` · base `af8c548` (E128)
Fecha: **D5 🟠** (filtro em `useState` morre no unmount — a vendedora filtrava a
fila, abria uma noiva, voltava: zerado, 3 gestos de novo a cada ida-e-volta; e
o link filtrado não viajava).
Suíte: API 873 · frontend 375 → 389 · E2E 147 · typecheck verde

## A primeira ação: o inventário dos nomes que já existem

`grep -l useSearchParams src/pages` devolve **18 telas** já no lado certo, e o
inventário de params deu a convenção: `ini`/`fim` (4×), `filtro`, `dia`,
`competencia`, `recorte`, `tipo`, `data`, `quando`, `vista`… Nenhuma tela
usava `q` na URL ainda — mas `q` é o nome do param de busca do SERVIDOR
(`listLeads`/`listContratos`/`listOrcamentos`), então a busca na URL usa o
mesmo nome que ela tem na API. Correção ao diagnóstico: `noivas/index.tsx` e
`vestidos/index.tsx` já apareciam no grep por causa de `?vista=` (E68, lido só
no mount) e `?data=` — o defeito era o RESTO dos filtros dessas telas, não a
ausência total.

## O desenho: uma gramática pura, um hook fino

- **`lib/filtro-url.ts`** — `comFiltros(atual, mudanças, defaults)`: default
  fica FORA da URL (a rota nua continua sendo a tela padrão, e o bookmark
  antigo não muda de significado), vazio é ausência (busca apagada remove `q`,
  não deixa `q=`), e **o resto da URL é dos outros** (`?quando=historico`
  atravessa intacto — o caso do backlog). `paginaDaUrl` engole lixo
  (`pagina=abc` → 1). O codec do filtro por atributo de vestidos vira UM param
  legível (`atributos=id:op,id:op`) com ida-e-volta testada. **14 testes.**
- **`hooks/use-busca-na-url.ts`** — a digitação assenta (300ms) e vira `?q=`
  com `replace` (digitação não escreve história); quem manda é a URL (voltar
  adota o `q` no input, nunca o contrário); e mudar a busca zera `pagina` no
  MESMO gesto (cuidado c: buscar da página 3 devolve um vazio falso). O
  cérebro é o `comFiltros`; o hook é só o fio do React.

## As 6 migrações

| Tela | O que foi para a URL | Nota |
|---|---|---|
| `contratos/index.tsx` | `q`, `filtro`, `pagina` | mudança de filtro zera página no mesmo write |
| `orcamentos/index.tsx` | `q`, `filtro`, `pagina` | idem |
| `noivas/index.tsx` | `q`, `etapa`, `pagina`, `vista` | `?vista=funil` (E68) era lido só no MOUNT; agora o toggle escreve e lê a URL — conferir a ficha na página 3 e voltar volta NA página 3 |
| `atendimentos/index.tsx` | `q`, `vendedora`, `situacao`, `janela`, `tipo` | a mais cara do achado (5 filtros zerando juntos); filtragem segue client-side e INSTANTÂNEA — filtra pelo que se digita, a URL assenta 300ms atrás; `?quando=historico` preservado |
| `vestidos/index.tsx` | `q`, `tamanho`, `cor`, `categoria`, `atributos`, `disponiveis` | junta-se ao `?data=` que já morava lá; "Limpar filtros" vira UMA escrita e o input adota o vazio pela regra "a URL manda" |
| `financeiro/conciliacao.tsx` | `recorte=todas` | só o FILTRO — o extrato em memória não viaja num link (escopo do backlog) |

## Verificação

- **Vermelho-antes**: o comportamento, reproduzível em qualquer uma das 6 —
  filtrar, navegar, voltar, zerado (é o próprio achado D5, com o custo medido
  pela trilha: 3 gestos por ida-e-volta). O estado dos filtros não existia na
  URL: `grep` das 6 telas mostrava `useState` para cada filtro listado.
- **Depois, medido no app vivo** (script no navegador):
  1. digitar "mariana" em /contratos → `?q=mariana` na URL após o debounce;
  2. clicar "Cancelados" → `?filtro=CANCELADO`;
  3. abrir `/noivas?etapa=PERDIDO` direto → o select mostra "Perdido";
  4. `/atendimentos?situacao=AGENDADO` → navegar ao dashboard → voltar →
     `?situacao=AGENDADO` de pé.
- **Suítes**: frontend **389/389** (+14 de `filtro-url.test.ts`) · API
  **873/873** (nenhuma rota tocada) · **E2E completo 147/147** — os specs 05,
  54 e 55 exercitam busca e navegação nas telas migradas · typecheck verde.

## O que o plano errou (e o executor decidiu)

1. **O backlog pedia testes de MemoryRouter; o repo decidiu não ter infra de
   render** (E99, reafirmado no E121 e E125). Convertido no desenho padrão da
   rodada: a DECISÃO (gramática de escrita, leitura de página, codec) é pura e
   testada; a tela é fio. O smoke no navegador cobriu o que o render test
   cobriria.
2. **Debounce e URL têm uma armadilha dupla que o plano não menciona**: o
   efeito que escreve a busca não pode escrever no mount (apagaria a `pagina`
   de quem chegou por link) e não pode "devolver" o valor antigo quando a URL
   muda por navegação (senão o back-button perde o `q`). O hook resolve com
   uma ref do último valor escrito — é a razão de ele existir em vez de seis
   cópias do efeito.

## Visto de passagem

- `atendimentos/index.tsx` valida `situacao` contra as opções da VISTA
  (`situacaoValida`) — um `?situacao=CONCLUIDO` na fila (onde não é opção)
  degrada para TODAS em silêncio, que é o comportamento certo herdado do
  código existente; nada a consertar.
