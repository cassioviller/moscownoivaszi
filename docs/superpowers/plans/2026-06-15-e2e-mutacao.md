# Suíte E2E com mutação (Playwright) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Elevar o scaffold Playwright read-only (não commitado) para uma suíte que dirige a UI real nos quatro fluxos de escrita (cadastrar noiva, cadastrar vestido, agendar atendimento, fechar contrato), com todos os dados isolados numa loja efêmera `loja-e2e` que nasce no setup e é destruída no teardown.

**Architecture:** `globalSetup` cria via Prisma direto a `loja-e2e` + usuário admin dela + pré-requisitos (cabine, horário); `globalTeardown` apaga a loja (cascade) e o usuário. Cada spec autentica como esse admin, cria suas pré-condições por fixture Prisma e exercita a mutação **pela UI**, afirmando o efeito observável na tela. A suíte roda serial contra o dev server (`reuseExistingServer` na :5000).

**Tech Stack:** `@playwright/test` (Chromium via `REPLIT_PLAYWRIGHT_CHROMIUM_EXECUTABLE`), Prisma 7 + `@prisma/adapter-pg` (mesmo client gerado em `src/generated/prisma`), bcryptjs.

**Spec:** `docs/superpowers/specs/2026-06-15-e2e-mutacao-design.md`

## Convenções do ambiente (ler antes de rodar)

- Node às vezes fora do PATH; rodar a suíte com `npm run test:e2e` (que chama `playwright test`). Se `npm` faltar no PATH, ele está em `/nix/store/*/bin`.
- O dev server na :5000 é gerido pelo Replit; `reuseExistingServer: true` o reaproveita. **Garanta que o app está no ar antes de rodar a suíte** (ou deixe o Playwright subir o seu num ambiente sem server — mas a trava de instância única do Next 16 impede 2 dev servers).
- `tsc`/`vitest` continuam como gates do commit na `main`: `node node_modules/typescript/bin/tsc --noEmit` e `node node_modules/vitest/vitest.mjs run`.
- Pré-requisito de dados: o `globalSetup` é autossuficiente (não depende do seed). Mas o Postgres de dev precisa estar no ar com as migrações aplicadas.

**Fatos do código real (verificados) usados pelos specs:**
- Perfil admin global tem id estável `"perfil-admin"` (`src/lib/admin/perfis-ids.ts`); `podeNoModulo` libera tudo quando `vinculo.perfilId === "perfil-admin"`. O admin e2e é vinculado a esse perfil → acesso total à `loja-e2e` sem ser super-admin (1 loja → login auto-seleciona).
- `RegraDisponibilidade` tem `atendimentoAberturaHora`/`atendimentoFechamentoHora` (default 9/19) → slots de 1h. `Cabine { lojaId, nome }`.
- Noiva: `/noivas/nova`, form com `name="noivaNome"` (required), botão `type=submit`. Lista `/noivas` mostra o nome em `<h2>`.
- Vestido: `/vestidos/novo`, fields `name="codigo"`, `name="nome"`, `name="precoBase"` (required). Lista `/vestidos` mostra nome + código.
- Agendar: `/atendimentos/novo`; selects com `aria-label` **Noiva**, **Cabine**, **Vendedora**; input `aria-label="Data"`; slots são `<button>` com texto `"09:00 – 10:00"` (en-dash), `disabled` quando ocupado; botão `Agendar`. Sucesso → redireciona para `/atendimentos/novo?ok=1`. A fila `/atendimentos` lista a noiva por nome. `listarEquipe` inclui o admin e2e como vendedora.
- Contrato: no perfil da noiva, botão **"Gerar contrato em branco"** (só com `contratos.length === 0`) → `/contratos/{id}`. No detalhe: com 0 parcelas, input `aria-label="Número de parcelas"` (default 1) + botão **Gerar**; depois `<details>` com `<summary>Cancelar contrato</summary>`, radios `name="destinoPago"` (manter/estornar), input `aria-label="Motivo do cancelamento"`, botão **Confirmar cancelamento**. Parcela cancelada renderiza o texto `· cancelada`; o status do contrato vira `Cancelado`.

```ts
import type { Page } from "@playwright/test";

// Loja e credenciais EFÊMERAS criadas pelo globalSetup (ver e2e/fixtures.ts).
// Sobrescrevíveis por env para CI.
export const LOJA = process.env.E2E_LOJA ?? "loja-e2e";
export const EMAIL = process.env.E2E_EMAIL ?? "admin-e2e@moscow.local";
export const SENHA = process.env.E2E_SENHA ?? "e2e-12345";

/** Autentica e sai da tela de /login. Não escolhe loja. */
export async function login(page: Page): Promise<void> {
  await page.goto("/login");
  await page.fill("#email", EMAIL);
  await page.fill("#senha", SENHA);
  await page.click('button[type="submit"]');
  await page.waitForURL((u) => !u.pathname.endsWith("/login"));
}

/** Autentica e garante LOJA como loja ativa (1 loja → auto-seleção server-side). */
export async function entrarNaLoja(page: Page): Promise<void> {
  await login(page);
  await page.goto("/selecionar-loja");
  if (page.url().includes("/selecionar-loja")) {
    await page.check(`input[name="lojaId"][value="${LOJA}"]`);
    await page.click('button[type="submit"]');
    await page.waitForURL((u) => !u.pathname.endsWith("/selecionar-loja"));
  }
}
```

- [ ] **Step 2: Criar `e2e/fixtures.ts` (Prisma direto, idempotente, com guard)**

```ts
import { PrismaClient } from "../src/generated/prisma/client";
import { PrismaPg } from "@prisma/adapter-pg";
import bcrypt from "bcryptjs";
import { LOJA, EMAIL, SENHA } from "./helpers";

// Prisma 7 exige driver adapter no construtor (mesmo padrão do prisma/seed.ts).
const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL });
export const prisma = new PrismaClient({ adapter });

const ADMIN_ID = "usuario-e2e-admin";
const PERFIL_ADMIN_ID = "perfil-admin"; // id estável do seed; podeNoModulo libera tudo p/ ele.
const LOJAS_REAIS = new Set(["loja-moscow", "loja-teste-2"]);

/** Cria a loja efêmera + admin + pré-requisitos do agendamento. Idempotente. */
export async function prepararLojaE2E(): Promise<void> {
  if (LOJAS_REAIS.has(LOJA)) throw new Error(`E2E_LOJA "${LOJA}" colide com uma loja real — abortando.`);

  // Corrida anterior órfã: o cascade da Loja leva todo dado de tenant.
  await prisma.loja.deleteMany({ where: { id: LOJA } });
  await prisma.usuario.deleteMany({ where: { email: EMAIL } });

  await prisma.loja.create({ data: { id: LOJA, nome: "Atelier E2E (efêmero)" } });

  // Perfil Admin global (id do seed). Upsert não-destrutivo se já existir.
  await prisma.perfil.upsert({
    where: { id: PERFIL_ADMIN_ID },
    update: {},
    create: { id: PERFIL_ADMIN_ID, nome: "Admin", acessosModulos: {} },
  });

  const senhaHash = await bcrypt.hash(SENHA, 10);
  await prisma.usuario.create({
    data: { id: ADMIN_ID, nome: "Admin E2E", email: EMAIL, senhaHash, isSuperAdmin: false },
  });
  await prisma.usuarioLoja.create({
    data: { usuarioId: ADMIN_ID, lojaId: LOJA, perfilId: PERFIL_ADMIN_ID },
  });

  // Pré-requisitos do fluxo de agendamento.
  await prisma.regraDisponibilidade.create({
    data: { lojaId: LOJA, atendimentoAberturaHora: 9, atendimentoFechamentoHora: 19 },
  });
  await prisma.cabine.create({ data: { lojaId: LOJA, nome: "Cabine E2E" } });
}

/** Apaga tudo que o setup criou. Cascade da Loja leva o dado de tenant. */
export async function limparLojaE2E(): Promise<void> {
  await prisma.sessao.deleteMany({ where: { usuario: { email: EMAIL } } });
  await prisma.loja.deleteMany({ where: { id: LOJA } });
  await prisma.usuario.deleteMany({ where: { email: EMAIL } });
}

/** Pré-condição de spec: cria uma noiva na loja e2e, retorna o leadId. */
export async function criarNoivaE2E(noivaNome: string): Promise<string> {
  const lead = await prisma.lead.create({ data: { lojaId: LOJA, noivaNome } });
  return lead.id;
}
```

```ts
  await page.getByText("Cancelar contrato").click(); // abre o <details>
  await page.getByRole("button", { name: "Confirmar cancelamento" }).click();
  await page.waitForURL(/ok=cancelado/);

  // Efeito observável: status Cancelado + parcelas canceladas.
  await expect(page.getByText("Cancelado")).toBeVisible();
  await expect(page.locator("text=/· cancelada/").first()).toBeVisible();
```

## Riscos e mitigações

- **Import do Prisma client no globalSetup falha (ESM/CJS ou path):** o client é gerado em `src/generated/prisma`. Se o loader do Playwright reclamar, mover a lógica de `prepararLojaE2E`/`limparLojaE2E` para um script `tsx` (`scripts/e2e-setup.ts`) e invocá-lo do globalSetup via `child_process` (`node node_modules/tsx/dist/cli.mjs scripts/e2e-setup.ts`), espelhando como `prisma/seed.ts` já roda. A interface dos specs (`criarNoivaE2E`) continua importando de `fixtures.ts` no worker, que é contexto Node normal.
- **Vitest tentando rodar os `.spec.ts` de `e2e/`:** o Vitest e o Playwright usam `test`/`expect` de pacotes diferentes. Garantir que o `include` do Vitest aponta só para `src/**` (ou adicionar `exclude: ["e2e/**"]`). Verificado no Task 7 Step 3.
- **Grade não carrega o slot a tempo:** a grade vem por server action com `useTransition`; usar `await expect(slot).toBeEnabled()` antes do click dá a espera explícita (o `expect.timeout` é 10s no config).
- **Teardown não roda (processo morto):** o `prepararLojaE2E` é idempotente (apaga `loja-e2e`/usuário órfãos antes de recriar), então a próxima corrida se autolimpa.
- **Dev server fora do ar:** sem server na :5000 e com a trava de instância única do Next 16, a suíte não sobe. Garantir o app rodando antes (`npm run dev` ou o botão Run do Replit).
