# Spec S0.2 — Provas (visão dedicada)

> **Fatia** do roadmap `2026-06-03-roadmap-comercial-financeiro-comissao-design.md`.
> **Aquecimento** — independente. Fina e read-first. Sem migração, sem mudar provas.

## 1. Problema

A operação de provas existe (`src/lib/atelier/provas.ts`) mas só é vista **dentro de
cada reserva**. Falta um lugar único — a **agenda de provas do atelier** — para a equipe
ver, num relance, as provas que vêm aí (e o histórico). O link "Provas" já está na
sidebar (seção Ateliê) apontando para `/loja/[id]/provas`, hoje **404**.

## 2. Escopo

**Dentro:**
- Data layer `listarProvasDaLoja(lojaId, { passadas? })` — provas da loja com noiva,
  vestido e reserva, ordenadas por data (espelha `listarReservasDaLoja`/fila de ajustes).
- Página `/loja/[id]/provas`: lista as próximas provas (e um filtro para o histórico),
  cada linha com data, noiva, vestido, tipo, comparecimento e **link para a reserva**.
- Teste de integração do data layer.

**Fora (YAGNI / já existe na reserva):**
- Registrar/editar/remarcar prova e marcar comparecimento **inline** — continua no
  detalhe da reserva (onde a action e a permissão `ajustes:*` já vivem). A tela dedicada
  **deep-linka** para lá. (Marcar comparecimento inline fica para uma fatia futura, se
  pedido.)
- Qualquer mudança no schema/motor.

## 3. Data layer

Arquivo: `src/lib/atelier/provas.ts`.

```ts
export type ProvaDaLoja = {
  id: string;
  dataReal: Date;
  tipo: ProvaTipo;
  comparecimento: ProvaComparecimento;
  bloqueioId: string;       // reserva (deep-link)
  leadId: string | null;
  noivaNome: string | null;
  vestidoCodigo: string;
  vestidoNome: string;
  casamentoData: Date | null;
};

/** Provas da loja com noiva+vestido. Padrão: próximas (dataReal ≥ hoje, asc);
 *  `passadas` traz o histórico (dataReal < hoje, desc). Escopo de loja. */
export async function listarProvasDaLoja(
  lojaId: string,
  opts?: { passadas?: boolean },
): Promise<ProvaDaLoja[]>;
```

- `tenantPrisma(...).prova.findMany` com `include: { bloqueio: { include: { lead, vestido } } }`.
- Filtro por `dataReal` relativo a **hoje** (convenção São Paulo → meia-noite UTC, igual a
  `listarReservasDaLoja`). Ordena asc (próximas) ou desc (passadas).

## 4. Página

`/loja/[id]/provas/page.tsx` — Server Component, `force-dynamic`.

- **Permissão de ver:** `leads:ver` OU `ajustes:ver` (mesma lente do detalhe da reserva).
  Sem nenhum → volta para o início.
- **Layout Concierge:** título "Provas" + subtítulo humano; filtro Próximas/Anteriores
  (query-param `passadas`, igual ao livro de Reservas). Lista calma, sem tabela hostil.
- **Cada linha:** data (longa), tipo (1ª/intermediária/final), noiva, vestido, badge de
  comparecimento, e "casamento DD/MM". A linha (ou um link) leva a
  `/loja/[id]/reservas/[bloqueioId]`, onde se registra/edita.
- **Vazio:** "Nenhuma prova por aqui ainda." (humano, sem alarme).

## 5. Testes

Estender `src/lib/atelier/__tests__/atelier.test.ts` (ou um bloco novo):
1. `listarProvasDaLoja` traz a prova da loja com noiva e vestido corretos.
2. Ordenação por data (asc nas próximas; desc nas passadas).
3. Filtro período: próxima aparece em "próximas" e não em "passadas" (e vice-versa).
4. Isolamento: provas de outra loja não aparecem.

## 6. Plano

1. Data layer + testes (TDD).
2. Página + filtro + deep-link.
3. Verificar que o link "Provas" da sidebar abre a tela (não mais 404).
4. Gates verdes (`tsc`, `vitest`) e commit.

## 7. Definição de pronto

`/provas` lista as provas da loja por período, cada uma linkando para sua reserva; data
layer coberto por teste; o link da sidebar deixa de ser 404; gates verdes.
